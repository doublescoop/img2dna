How img2dna turns a picture into DNA

This page walks through the exact pipeline the img2dna site runs. Every number below is computed live using the same code as js/bundle.js, on a small 16×10 drawing you can edit. Constants: W = image width · GR_K = 5 · MARKER = TCCG · chunk header = guard (1 bit) + salt (16 bits).

1 Preprocess→ 2 B&W pixels→ 3 Run lengths→ 4 Golomb-Rice→ 5 Chunks→ 6 Header + salt→ 7 Trits → DNA→ 8 Salt search→ 9 Marker + output→ 10 Decode

1Preprocess the photo into black and white

We only store black or white for each pixel, so the photo is reduced to pure black and white first.

  1. Resize to the target width W (default 200 px), up or down, keeping the aspect ratio. Pixels are not blended (nearest neighbour).
  2. Grayscale: g = 0.2989·R + 0.587·G + 0.114·B
  3. Contrast around mid-gray: g = (g − 128) × contrast + 128, clamped to 0–255.
  4. Threshold: g < threshold → black, otherwise white.

Try it on a gray ramp

Differs from the notebook. img2dna_soul_v11_GR.ipynb also removes large black blobs touching the border, crops to the content with a 10 px margin, only ever shrinks, and uses PIL's contrast (which centres on the image's average gray rather than 128). So the same photo can give a slightly different black-and-white image there. Everything from step 2 onward is identical in both.

2The black-and-white image

From here on the image is just a grid: W pixels per row, H rows. Click pixels to edit the drawing; every step below updates.

3Each row becomes a start colour + run lengths

Instead of listing every pixel, each row is stored as one bit for the colour it starts with (0 = black, 1 = white), followed by how long each stretch of the same colour is. Colours alternate, so they don't need to be stored. Runs in a row always add up to W. Click a row to inspect it.

4Golomb-Rice compresses each run length (k = 5)

Each run length becomes a short bit pattern. For run length L: take n = L − 1, split it into q = n ÷ 32 and r = n mod 32, then write q ones, a 0, and r as 5 bits. Runs up to 32 cost 6 bits; each extra 32 pixels costs one more bit.

5Pack whole rows into chunks

Each chunk becomes one DNA strand. Rows are added to a chunk until the next row would push it past the target body bits, then a new chunk starts. A row is never split. On the site the default is 3,000 bits (about 1,900 bases per strand); here it's small so the tiny drawing still makes several chunks.

6Add the header and scramble the body with a salt

The body bits are XOR-ed with a 16-bit salt, repeated as often as needed. XOR is reversible, so the decoder gets the body back by XOR-ing with the same salt. A different salt gives completely different DNA, which step 8 uses to find a strand that's safe to synthesize. In front go a guard bit 1 and the salt itself.

7Bits → trits → DNA bases

The chunk's entire bit string is read as one big binary number and rewritten in base 3 (trits: 0, 1, 2). Each trit picks the next base from the table below, based on the previous base. The next base is never the same as the previous one, so no AA/CC/GG/TT ever appears. The guard bit stops leading zeros from vanishing in the conversion.

8Salt search: keep trying salts until the strand is safe

For each chunk the encoder tries salts 0, 1, 2 … up to 65,535, repeating steps 6–7, and keeps the first one that passes. It searches in up to three passes, easing the rules only if a whole pass fails:

No bases are ever patched or replaced, so the image always decodes exactly.

9Join chunks with the TCCG marker

Every chunk is prefixed with TCCG. It contains CC, which the FSM can never produce, so the marker can't appear by accident inside a chunk. The site offers the result as one DNA string or as FASTA (one record per chunk).

10Decode, including from missing pieces

Each chunk decodes on its own, so a partial set of strands still gives part of the picture. Click a chunk to drop it. Rows are painted top to bottom in the order they arrive, so dropping a chunk moves the rows after it up rather than leaving a gap.

Decoder spec (what a biologist needs)

  1. Drop lines starting with > or #; keep only A/C/G/T, uppercase.
  2. Split on TCCG. Each piece is one chunk.
  3. DNA → trits with the FSM table in reverse (the start row for the first base).
  4. Trits → one big number → bits.
  5. The first 1 is the guard. The next 16 bits are the salt.
  6. XOR the remaining bits with the salt, repeated every 16 bits.
  7. Repeat until bits run out: read 1 bit (row start colour, 0 = black), then Golomb-Rice decode run lengths (k = 5) until they add up to W. Paint that row with alternating colours.
  8. Paint rows top to bottom on a white canvas, W pixels wide.
